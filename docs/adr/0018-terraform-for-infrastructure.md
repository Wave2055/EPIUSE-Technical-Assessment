# ADR-0018: Define all infrastructure in Terraform

- **Status:** Accepted; `database/` module replaced by a data volume and backups per [ADR-0023](0023-postgresql-container-on-the-api-instance.md); state locking per [ADR-0028](0028-lock-terraform-state-with-s3.md)
- **Date:** 2026-10-15
- **Deciders:** Jaitin
- **Related:** [ADR-0015](0015-ec2-docker-for-api-compute.md), [ADR-0017](0017-omit-nat-gateway-use-ssm.md), [ADR-0021](0021-credit-funded-run-rate-and-teardown.md)

## Context

The deployment spans a VPC with two subnet tiers, security groups, an EC2 instance with an instance profile, RDS, two S3 buckets, a CloudFront distribution with two origins and an OAC, ECR, and Secrets Manager. That is well past the point where console clicking is reproducible or explicable.

Two further pressures apply specifically to an assessment:

- The technical document must explain the architecture. Infrastructure code _is_ that explanation, in a form that cannot drift from reality.
- The deployment runs on time-limited credits and **must be torn down** ([ADR-0021](0021-credit-funded-run-rate-and-teardown.md)). Reliable teardown requires a complete inventory of what was created — which is exactly what a state file is.

## Decision

Define all infrastructure in **Terraform**, under `infra/`, organised into modules:

```
infra/
  main.tf  variables.tf  outputs.tf  versions.tf
  modules/
    network/   VPC, subnets, IGW, security groups (no NAT — ADR-0017)
    database/  RDS, subnet group, SG rules, generated password → Secrets Manager
    compute/   EC2, EIP, IAM instance profile (SSM/ECR/S3), user-data
    storage/   avatars bucket, web bucket, CloudFront + OAC (ADR-0016)
    registry/  ECR repository with a lifecycle policy
```

**Secrets are never written to `.tf` files or committed.** The RDS password and the JWT signing key ([ADR-0014](0014-self-hosted-jwt-auth-and-salary-masking.md)) are generated by Terraform directly into Secrets Manager and read by the container at boot through the instance role.

State is held in S3 with a DynamoDB lock table. Local state is acceptable for a single-author assessment, but the remote backend is configured because a `terraform.tfstate` containing resource attributes must never be committed to the repository the assessors receive.

## Consequences

### Positive

- The entire environment is reproducible from `terraform apply`, and destroyable with `terraform destroy` — which the cost model depends on.
- The infrastructure is reviewable in the git repository the brief requires, alongside the application code.
- `terraform plan` makes the blast radius of a change visible before it is applied.
- Module boundaries document the architecture's tiers directly.

### Negative

- Terraform is a second toolchain and language in an otherwise all-TypeScript repository — the explicit trade made against AWS CDK.
- State is itself critical and sensitive: losing it orphans resources that then bill silently; the state file contains resource attributes and must be treated as confidential.
- CloudFront distributions take 15+ minutes to create or modify, making apply cycles slow.
- Terraform cannot express everything: the container's lifecycle on the instance is handled by user-data and SSM ([ADR-0019](0019-github-actions-oidc-cicd.md)), so there is a seam between "infrastructure" and "deployment".

## Alternatives considered

- **AWS CDK in TypeScript.** Would keep the repository to one language, share types with the application, and give loops and conditionals in a real language. Genuinely attractive given [ADR-0003](0003-typescript-monorepo-with-shared-schemas.md). Rejected at the project owner's direction in favour of Terraform's wider industry recognition and cloud-agnostic syntax.
- **CloudFormation directly.** No extra tooling, native to AWS. Rejected: verbose, poor module ergonomics, and weaker than Terraform at reviewing a plan before applying.
- **Console clicks plus a written runbook.** Fastest to a live URL. Rejected: not reproducible, drifts immediately, impossible to review, and makes complete teardown a manual hunt — a real risk when spending limited credits.
